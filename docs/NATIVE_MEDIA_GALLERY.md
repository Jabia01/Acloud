# Native media gallery — 2026-10-16

Library now browses the accessible on-device Photos library as a dated thumbnail grid, rather than only scan totals. Media filters, newest/oldest sorting and three thumbnail sizes are shared with Backup and Restore. Library loads metadata in pages of 200; ordering applies to the PhotoKit fetch before paging. Limited Photos access stays limited. Photo-page reads run in a dedicated actor with loading feedback; browsing/permission checks do not depend on the optional scan database opening. Permission/library refresh clears stale gallery entries. The existing metadata scanner remains separate under scan details.

Select mode uses a whole-tile tap, highlighted border and checkmark instead of Restore's switches. Selection alone cannot upload or restore. The existing maximum-ten policies and authenticated backup/restore gates still govern explicit action buttons. Selection stays visible in a bottom action bar and survives sorting/refresh. Selected IDs are revalidated against current PhotoKit access, including selections outside the newly loaded page. Library can queue an explicitly selected batch through the existing backup model; its result offers a route to Transfers. Restore keeps duplicate-copy confirmation and all existing access/integrity/save controls.

Backup has Gallery and Transfers views, with the mode switch at the top. The Gallery view keeps its add action compact; detailed options remain in Transfers. Restore places the gallery above a collapsed options/information section. Gallery shows completed ordinary items and one protected still/render per complete image manifest from the loaded queue page; incomplete resource sets stay in Transfers. Transfers retains detailed byte/checking/completion progress, status filters, pagination and completeness information. The gallery is labelled as a view of loaded transfers, not an exhaustive cloud inventory.

Tap a tile to open a shared swipeable viewer with previous/next controls, date and source label. Local image previews and local video playback use PhotoKit with network access disabled; unavailable iCloud originals are not silently downloaded. Device video playback requires a local AVURLAsset. This presentation does not implement Live Photo motion or adjustment-history editing. Shared Backup/Restore row thumbnails also open the viewer.

Saved-backup viewers use the private checksum-bound thumbnail cache from the previous change. They explicitly describe reduced-resolution previews and the need to restore a copy to Photos for full-quality inspection/video playback. An old saved thumbnail can be generated only through the existing explicit, bounded Wi-Fi download flow. No device rendition substitutes for a saved version. This pass does not add full-resolution cloud streaming, favorites, albums, search by photo content or cloud deletion controls.

Validation and device installation are recorded in the project ledger. Simulator workflow checks passed using generated media and the fresh simulator’s stock photos: selecting a tile, retaining selection after refresh, filtering videos, opening a photo viewer and opening a video viewer. Existing batch-selection policy checks also passed. Photos read and add permission were granted only in the disposable simulator. This is not a live cloud restore or physical-device visual acceptance test.
